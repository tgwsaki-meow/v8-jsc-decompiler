## Oracle self-check

Each oracle has to be shown both that it accepts an identical program and that it rejects a one-token change; without the second, an oracle that always answers "match" passes the first.

| check | result |
|---|---|
| O1 identity (an identity decompiler scores 100% exact) | PASS |
| O1 discrimination (a one-token mutation is not exact) | PASS |
| O2 mechanism control (`cachedDataRejected` false for the same source, true for a mutated one) | PASS |
| O3 identity (the same file twice traces identically) | PASS |
| O3 discrimination (a one-token mutation changes the trace) | PASS |
| O3 execution policy (refuses to run `decompiled_js/`) | PASS |

Self-check entries: accessor-defineproperty, async-function, class-methods, decl-var.

**O1 blind spot, measured.** values inside boilerplate constants (array / object literals): V8 prints the boilerplate descriptor, never the element values -- on node (pool dumped) as well as d8 (pool partial). Evidence: `scratch/t3/probe_pool.mjs`. Mutations that O1 could not see in this run: none. O3 sees these, which is part of why three oracles are needed rather than one.

## How to re-run

```powershell
node corpus/check.mjs                      # the corpus itself must be sound first
node src/verify/run_oracles.mjs --selfcheck # the instruments must pass their own checks
node tools/metrics/run.mjs --quick         # this document
node tools/metrics/run.mjs --full          # wide samples; hours
```

Per-collector artifacts and logs are in `scratch/t3/metrics/`. A collector that fails leaves its log and a `_failed` row rather than taking the run down.
